Там сервис лежит в /opt/VoIP_PBX_Service  
  
НЕ ЗАМЕНЯТЬ ФАЙЛ appsettings.json!!! Он скорректирован именно под эту машину(путь к лог файлу и сертификат).  
  
Для обновления достаточно загрузить обновленные файлы, не заменяя файл настроек appsettings.json  
Если не изменяли версии библиотек то должно быть достаточно одного VoIP_PBX_Service.dll  
  
путь к логам в appsettings.json, сейчас в /var/logs/папка сервиса


  
В гит залит сервис VoIP_PBX_Service  
написан на .net8  
[https://dotnet.microsoft.com/ru-ru/download/dotnet/8.0](https://dotnet.microsoft.com/ru-ru/download/dotnet/8.0)  
так же, так как это сервис с API, то по ссылке выше нужно Hosting Bundle  
  
Настройки сервиса в appsettings.json и appsettings.Development.json  
Файл настроек используется в зависимости от переменной окружения ASPNETCORE_ENVIRONMENT  
Если она есть и в ней Development - то будет использоваться второй файл  
Использование нескольких сред описано в [https://learn.microsoft.com/ru-ru/aspnet/core/fundamentals/environments?view=aspnetcore-8.0](https://learn.microsoft.com/ru-ru/aspnet/core/fundamentals/environments?view=aspnetcore-8.0)  
Для запуска из студии в режиме отладки достаточно в файле Properties\launchSettings.json в разделе environmentVariables раскомментировать "ASPNETCORE_ENVIRONMENT": "Development" //включение конфигурации разработчика. Но при запуске выполняемого файла вне среды разработчика - не работает(учитываются только переменные среды ОС).  
  
В самом проекте в Program.cs загружаются настройки для клиента Minio(S3)  
остальное при инициализации контроллера VOIPController  
В сервисе несколько функций к которым можно обратиться  
По адресу https://[адрес]:[порт из настроек]/voip/check - можно проверить что порт открыт и сервис запущен, он ответит Ok и запишет в лог Success.  
  
По адресу /voip/pbxusers можно получить пользователей из PBX (возможно стоит закрыть)  
  
По адресу /voip/api сервис ожидает события из PBX, этот адрес прописывается в PBX в настройках сервиса elma365  
Сервис ожидает сообщение определенного формата, и затем пересылает его в RabbitMQ с ключем VoIP.Событие.PBX_Event, при несоответствии формату выдаст ошибку.  
На любое сообщение подходящего формата где Action не "pbxEvent" сервис ответит Ok(например на событие подключения от PBX).  
Если у подходящего сообщения есть поле RecordUrl то сервис попробует загрузить файл в Minio, и подменить ссылку на расположение файла в minio. Не получится напишет в лог ошибку и пошлет как есть.
